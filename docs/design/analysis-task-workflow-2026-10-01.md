# 面向分析任务的人机交互设计

日期：2026-10-01。范围：现有计算模块的交互组织，不扩大模型能力，也不将界面功能称为方法创新。

## 任务与对象

典型任务是保存初始方案，修改设备或线路参数，重新求解，并比较稳定性分类、振荡模态与模型近似误差。作者 MATLAB/Simplus 已支持调参与模型分析；软件增量应以操作时间、人工转录次数及案例复算成功率衡量，而不是“首次实现调参”。

四个工作区必须始终显示模型名称、输入来源及运行方式：固定论文算例、冻结参数域、可编辑低频网络、可编辑单机平均值模型。不能让共同的页面外观暗示其结果可直接互换。

## 已有能力与断裂处

| 环节 | 已有能力 | 需要补齐或纠正 |
|---|---|---|
| 输入 | 平均值模型参数分组；低频网络画布、属性编辑、撤销重做 | 尚无跨次运行的基线—候选方案比较；平均值模型保存项不含完整仿真设置，且没有对应的导入入口 |
| 工作点 | 平均值模型先求解并核对残差、功率平衡 | 前端仅显示合并忙碌状态；后端没有阶段进度时，不虚构“已完成工作点”或百分比 |
| 分析 | 平均值模型计算极点、响应与端口导纳；低频网络计算同步模态 | 当前网络画布不生成任意多设备平均值模型，不能宣称画布中的网络已完成论文判据核查 |
| 比较 | 当前模型上的预设42点层级扫描；固定19点消融与四条临界边界 | 42点扫描读取当前模型，只固定 D–X 网格；原提示错误地称所有任务冻结，需按实际行为纠正 |
| 导出 | JSON、CSV、HTML报告 | 平均值模型报告按当前输入重新求解，不直接使用完成结果；有必要绑定已完成请求的输入 |

### 首要缺陷：旧请求返回覆盖新输入

代码检查发现：`AverageDQWorkbench.tsx` 的 `analyze` 直接将异步返回值写入结果；输入控件在运行期间仍允许编辑。编辑虽清空结果，旧请求随后仍会重新显示旧参数计算结果。报告又读取当前输入，可能与屏幕对应不同工况。低频工作区也有相近模式，但本次修复先限制在平均值模型，避免多代理重叠。

本轮已修复主分析与层级扫描的请求归属，并以浏览器拦截延迟响应验证。测试使用明确标注的合成数据，只核查交互状态，不验证数值模型。

## 界面结构

1. 顶部：案例名称、模型名称、输入来源、参数修订状态；主操作为“运行分析”。
2. 左侧：当前选中元件或参数组；图形位置与电气参数分开保存。先沿用现有分组，不大改视觉样式。
3. 中央：模型或网络画布；结果页显示稳定性分类、工作点质量、全谱极点，按需切换响应与端口导纳。
4. 结果摘要：模型维数、最大极点实部（单位 s⁻¹）、振荡频率（单位 Hz）、计算输入及运行标识。充分判据未覆盖与闭环参考失稳分别显示。
5. 后续比较区：用户主动将成功结果设为“基线方案”，保留输入快照；候选方案显示具体参数差异和对应结果。不同模型仅在明确对齐假设、工作点与参数后比较。
6. 研究任务保持独立入口：层级扫描显示当前模型与预设网格，固定任务显示冻结锚点；研究结果不可静默充当当前输入的单工况分析结果。

## 状态与最小实施项

- 未运行：没有有效结果，不开放报告按钮。
- 计算中：记录不可变输入快照和请求标识；允许编辑，但编辑立即使该请求对当前输入失效。
- 参数已修改：清空当前结果与报告快照；旧请求无论成功或失败都不得恢复过期结果或错误。参数改回原值也不恢复旧请求资格。
- 已完成：仅接受最新有效请求；JSON导出与报告使用该成功结果绑定的输入。
- 失败：只显示仍有效请求的错误；不留下“已完成”的旧结果。
- 重复操作：同步请求锁防止同一请求发起前的连击；不依赖按钮下一次渲染才生效。
- 切换离开：取消前端结果接收资格；不声称停止后端计算，除非实际有中止接口。

请求快照、修订校验、同步请求锁与报告输入绑定已实施，编辑仍然可用。报告接口目前仍按快照重新计算，尚未变为直接读取完成结果，因此不保证两次计算的运行标识相同。下一步再做基线—候选方案比较。图表交互和视觉令牌暂不改动。

## 交互核查

1. 将分析响应延迟，运行后修改阻尼：旧响应到达后无结果、无报告；输入保持新值。
2. 修改阻尼后改回原值：旧请求仍不被接受；重新运行后才形成有效结果。
3. 同步连击运行：只发送一次分析请求；有效失败允许重试。
4. 旧请求失败时已修改输入：不显示旧工况的失败信息。
5. 成功后导出报告：请求体与成功分析输入逐字段相同；报告按钮在新参数编辑后不可用。
6. 离开工作区后旧响应到达：不更新已卸载组件；回到工作区按其初始化语义重新开始。
7. 只运行定向测试和 TypeScript/生产构建；此次不运行刚性扫描或 MATLAB 全量计算。

实际验证：`npm run build` 通过 TypeScript 与 Vite 构建（保留已有的大包体积提示）。`node scripts/test_average_dq_request_consistency.mjs` 的9组浏览器交互场景通过，包括延迟成功、改回原值、过期错误、连击、报告快照、失败重试、层级扫描失效、仿真设置独立性及离开工作区。测试启动自己的临时静态服务并在结束时关闭，不复用或停止已有服务。

## 方法与官方案例

- [MathWorks Property Inspector](https://in.mathworks.com/help/simulink/slref/propertyinspector.html)：属性面板随当前选中模型对象更新。借鉴上下文编辑，不复制专有界面或源码。
- [NN/g：系统状态可见性](https://www.nngroup.com/articles/visibility-system-status/)：及时反馈操作与当前状态；据此明确区分运行、输入修改、失败和可用结果，不以空白图表代替提示。
- [Apache ECharts：事件与动作](https://echarts.apache.org/handbook/en/concepts/event/)：后续以点选模态、频段缩放和对象联动服务分析；点击图表只改变观察对象，不暗中改变计算输入。

上述设计方法已有公开来源，属于人机交互与软件可靠性改进，不构成新的稳定性判据。
