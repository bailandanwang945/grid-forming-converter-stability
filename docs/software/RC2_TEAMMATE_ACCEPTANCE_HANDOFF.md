# v0.4.0-rc2 队友异机验收任务书

## 1. 验收对象

- 文件：`GFM-Stability-Platform-0.4.0-rc2-windows-x64.zip`
- 字节数：`70,660,054`
- SHA-256：`55c58253336f8e1a7b4132a097908e45ae2a26281f00ea2c5fb1e133468d2c3f`
- 源代码提交：`11eebebea1f6768855859e9ddbcf75a5e89db13c`

只验收这一原始 ZIP。不得用开发目录、旧版候选包或重新打包文件替代。

## 2. 权限边界

验收人员可以解压、运行、截图、录屏和导出结果；不得修改 ZIP、解压目录、源代码、清单或固定数据，不得为了运行而安装 Python、Node.js、MATLAB，不得全局关闭安全软件，也不得制作或修改 PPT/PDF。

若电脑已经安装开发环境，不要卸载。该电脑仍可完成“功能检查”，但不能据此关闭“异机、断网、无开发环境”验收门。

## 3. 自动验收

1. 将 ZIP 放到较短的本地路径，计算文件字节数和 SHA-256；二者必须与本任务书一致。
2. 完整解压，保留原始 ZIP，并使 ZIP 与同名解压目录相邻。
3. 断开 Wi-Fi、网线、热点、VPN 和其他互联网连接。
4. 双击 `VERIFY_THIS_PC.cmd`，按真实情况回答断网和开发环境问题。
5. 保存完整 `acceptance-results` 文件夹和结束窗口截图。

自动功能链通过应出现：

```text
GFM_CROSS_MACHINE_FUNCTIONAL_OK
```

只有机器条件真实满足、原始 ZIP 可追溯时，才应同时出现：

```text
GFM_M5_QUALIFIED
```

若出现 `GFM_M5_QUALIFICATION_INCOMPLETE`，只能报告“功能通过但M5资格不足”，不得改写成完整通过。

## 4. 人工浏览器检查

在仍然断网时双击 `GFM-Stability-Platform.exe`，逐项检查：

| 工作区 | 最低核对项 |
|---|---|
| 论文复现 | 失稳工况1000点、75个未覆盖点；稳定工况0个未覆盖点；有限网格边界可见 |
| 同域对照 | 176点，计数为45/96/35，且不把判据未覆盖写成系统必然失稳 |
| 低频模型 | 稳定预设可运行；修改阻尼后实际重算；模型排除动态可见 |
| 平均值 dq | 默认参考稳定、16个极点；42点层级扫描为39个一致、3个不一致、0个不可计算 |

至少实际导出并打开一份 JSON、一份 CSV 和一份打印式 HTML 报告，确认文件非空、中文正常、输入参数与当前页面一致。正常退出程序后，原本的本地网页应无法继续访问。

## 5. 失败纪律

失败时不得修改包内文件或安装依赖。保存完整错误、Windows版本、解压路径、安全软件信息、断网状态、运行时检测结果和 `acceptance-results`。只允许在不改变软件的前提下复核一次完整解压、原始 ZIP 位置和旧进程占用；同一错误再次出现后停止并回传。

## 6. 回传清单

- 完整 `acceptance-results`；
- ZIP 哈希与字节数截图；
- Windows版本、断网状态及自动验收结束截图；
- 四个工作区关键截图；
- 实际导出的 JSON、CSV、HTML；
- 正常退出或失败现场截图。

回传结论必须区分：

1. 自动功能链是否通过；
2. M5机器资格是否满足；
3. 人工浏览器与导出是否通过；
4. 候选包是否保持未修改。

只有四项证据均闭合，项目负责人才能在正式证据台账中关闭异机验收门。
