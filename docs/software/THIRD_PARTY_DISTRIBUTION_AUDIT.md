# 第三方组件与再分发审计

## 1. 审计目的

Windows 免开发环境候选包同时包含 Python 运行时、PyInstaller 嵌入模块、网页生产依赖和由作者代码形成的固定回归数据。仅在 README 中列出几个主要框架，不能证明发布包已经完整保留第三方许可信息。因此，构建流程现在从**实际可执行文件**与**锁定的网页生产依赖树**生成组件清单、许可原文副本和机器可读清单。

该审计解决的是“发布包中实际装入了什么、相应许可文本放在哪里”的可追溯问题，不构成法律意见，也不替代团队对本项目自有代码许可证的最终选择。

## 2. 构建期产物

每个 Windows 候选包根目录包含：

- `THIRD_PARTY_NOTICES.md`：供人阅读的组件、版本和许可标识汇总；
- `third-party-sbom.json`：供程序复核的组件清单；
- `licenses/`：从安装环境和上游包复制的许可、版权或通知原文；
- `release-manifest.json`：继续对上述文件逐一记录 SHA-256，防止许可清单脱离发布包或被静默替换。

生成程序会递归检查 PyInstaller 可执行文件中的模块，并通过当前 Python 环境的发行包元数据映射到组件；网页侧只纳入 `package-lock.json` 中非开发依赖。只要某个实际纳入的 Python 发行包或网页生产包找不到许可文件，构建即失败，而不是生成一份看似完整但实际缺项的清单。

## 3. 研究资料边界

候选包仅保留作者仓库的来源、固定版本和 MIT 许可，并包含由其 Fig. 8 算例形成的数值回归数据。以下内容不随软件包再分发：

- arXiv 论文 PDF 与 TeX 源文件；
- 作者 MATLAB 仓库的完整副本；
- MATLAB、Simulink 及其工具箱；
- Simplus 或其他时域仿真仓库。

因此，软件包内的来源声明不能被理解为论文、完整作者代码或商业软件的再授权。

## 4. 前端依赖收缩

原网页使用 `echarts-for-react` 作为轻量封装。为缩小依赖面并避免将缺少完整随包许可文本的间接依赖带入成品，当前版本改用项目内的 ECharts 生命周期适配组件。图表仍由 ECharts 渲染，交互与浏览器回归保持不变，但生产依赖树减少了三个包。该改动的价值在于降低发布审计复杂度，并非把第三方图表库包装成团队自研成果。

## 5. 尚未关闭的发布条件

- 团队尚未为项目自有源代码选择开源许可证，因此当前成品仍是结项候选包，而非正式公共发行版；
- Microsoft 运行时文件由 Windows Python/PyInstaller 工具链携带，清单中保留其存在与再分发条款提示；正式公开发布前仍应由项目负责人复核对应工具链条款；
- 每次依赖、Python 环境或打包工具版本变化后，必须重新生成清单，不得沿用旧候选包的组件数量。

在上述条件关闭以前，可以把候选包交给团队成员进行异机功能验收，但不应宣称许可证问题已经完成最终法律审查。
