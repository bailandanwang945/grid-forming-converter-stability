# 项目目标完成性审计

> 审计日期：2026-08-27
>
> 审计对象：`research/nontrivial-core` 分支与 Windows `v0.5.0-rc1` 内部结项候选
>
> 判定口径：以当前文件、可执行命令、运行结果和外部验收记录为证据；没有直接证据的事项不判为完成。

## 总体判断

当前状态为：**软件侧可汇报、可演示、可交付候选已经形成，但项目总体目标尚未全部完成。**

模型、接口、分析内核、适用范围内的拓扑与参数编辑、参数域分析、报告导出、自动测试、开发日志和本机便携式发布均有直接证据。尚未闭合的目标只有三类：合格异机断网复现及人工浏览器检查、项目自身代码许可证与公开分发决定、学院正式材料和指导教师审阅。

这意味着下一阶段不应继续增加模型或页面。除非异机验收发现可复现的软件缺陷，否则任何新研究功能都不进入 `v0.5.0-rc1`。

## 已验证事实与表述上限

1. 可以称“论文固定算例的有限网格结果得到受控复算”，不能称“论文连续全频定理已经由软件完整验证”。
2. 可以称“作者同一模型内观察到充分判据覆盖区相对于闭环特征根参考稳定区具有保守性”，不能把未覆盖点直接判为失稳。
3. 可以称“三状态模型与16状态模型在冻结42点网格中39点分类一致、3点失配”，不能外推为一般GFM降阶误差定理。
4. 可以称“Sienna Test 08完成分层方程核查”，不能称原始16状态与19状态整机已经同构或完成逐根特征值验证。
5. 可以称“Windows候选在开发机完成整包功能验收”，不能称“已经证明在其他电脑无需开发环境运行”。

## 未闭合但不阻断软件结项主线的问题

- 工作簿主导极点约 `0.578 Hz`，论文正文写约 `1.2 Hz`；失稳实部符号与有限网格回归不受影响，但振荡频率不能称定量复现。
- Simplus自动生成非线性模型的近奇异和异常初始化尚无完整因果解释，受污染响应不作为证据。
- 连续全频定理、准/半扇形扩展、多机构网系统、可信EMT、硬件在环和实物实验均不属于当前最小软件结项目标。
- Sienna原始整机仍有五项比较前提未闭合，状态保持 `not-ready`；这不是软件运行失败。

## 关闭总体目标前必须取得的证据

### 1. 合格异机证据

在无Python、Node.js、MATLAB和项目缓存的64位Windows电脑上断网运行 `VERIFY_THIS_PC.cmd`，同时取得：

```text
GFM_CROSS_MACHINE_FUNCTIONAL_OK
GFM_M5_QUALIFIED
```

随后按 `V050_RC1_TEAMMATE_ACCEPTANCE_HANDOFF.md` 完成四个工作区的人工浏览器、导出与退出检查，并回传完整 `acceptance-results`、截图和导出文件。

### 2. 项目侧复核

使用固定版本、提交和ZIP哈希导入异机证据。只有工具最终返回：

```text
GFM_CROSS_MACHINE_RELEASE_ACCEPTED
```

才可关闭跨机验收门。资格不足的本机证据返回 `GFM_CROSS_MACHINE_EVIDENCE_REJECTED` 属于预期结果。

### 3. 人工决策与行政材料

- 团队决定项目自身代码采用何种许可证，以及是否公开发布候选包；
- 取得适用于本项目批次的学院结项通知、模板、命名规则和截止时间；
- 指导教师审阅研究范围、主要结论、已知差异和演示口径；
- 团队完成人工讲解演练、签字和系统提交。

## 停止条件

在取得上述外部证据前，项目目标保持活动状态，但软件开发进入功能冻结。仅在异机验收发现可复现缺陷时修改 `v0.5.0-rc1`；许可证、学院材料或指导教师意见若改变发布边界，再建立新的候选版本。不得因为等待人工材料而继续堆叠新模型，也不得把“本机无报错”写成总体目标完成。
