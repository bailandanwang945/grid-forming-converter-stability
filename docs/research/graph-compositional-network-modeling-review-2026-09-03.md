# 图结构驱动的网络建模：方案调研与阶段决策

日期：2026-09-03

## 结论

“编辑网络”应升级为“网络建模与拓扑校核”。首版可以让用户添加、移动和连接元件，修改参数与开关状态，并把受支持的网络送入现有稳定性内核。但画布位置、电气拓扑和物理参数必须分别保存：移动图形不改变计算模型，改接端口或开合开关才改变拓扑，修改阻抗或控制参数才改变元件模型。

这里不采用“可加法学”这一非规范名称。准确表述为“基于图结构的可组合网络建模”；局部元件对全局矩阵的叠加过程称为“分块装配”或“局部贡献的可加组装”。

## 现有基础

现有 `NetworkTopology/1.0` 已支持母线、交流线路、构网型变流器、无限大母线和静态负荷。低频内核根据线路首末端和电抗组装加权拉普拉斯矩阵，以无限大母线为接地点，并对无动态母线执行 Kron 约简。因此，增删支路、改变线路端点、改变 VSM 接入点或线路电抗都会真实改变状态矩阵和闭环特征根。

当前前端仍是表单式编辑器：母线按数组顺序横向排列，没有图形坐标、端口、拖拽连线、开关或拓扑差异视图。线路电阻、并联电纳、负荷和运行设定值虽能进入数据契约，但不进入当前低频模型。界面不得暗示这些参数已经参与稳定性计算。

## 数学装配

每个元件 (e) 提供局部端口导纳 \(\widehat Y_e(s)\) 和端口选择矩阵 \(S_e\)，全网节点导纳写为

\[
Y_{\mathrm{bus}}(s)=\sum_e S_e^{\mathsf T}\widehat Y_e(s)S_e.
\]

对简单无损支路，可退化为节点—支路关联矩阵形式

\[
K=B\operatorname{diag}(1/X_e)B^{\mathsf T}
  =\sum_e X_e^{-1}b_eb_e^{\mathsf T},
\]

这正是现有低频内核逐支路组装拉普拉斯矩阵的形式。加入或删除一条支路相当于加入或删除一个局部项；修改单个元件参数产生稀疏或低秩增量

\[
\Delta Y_{\mathrm{bus}}
=S_e^{\mathsf T}\Delta\widehat Y_eS_e.
\]

对于论文判据，应自动保留所有变流器公共连接点，并将其余内部节点按

\[
Y_{\mathrm{red}}=Y_{\alpha\alpha}
-Y_{\alpha\beta}Y_{\beta\beta}^{-1}Y_{\beta\alpha}
\]

执行 Kron 约简，得到论文中的 \(Y_{\mathrm{net}}(s)\)。每台变流器的端口导纳仍按块对角结构组成 \(Y_C(s)\)。这一编译链与论文 v2 的网络定义一致，但“可以编辑拓扑”本身不能证明判据保守性已经降低。

## 软件分层

1. `ElectricalGraph`：母线、元件、端口、连接、开关状态和稳定 ID，是计算的唯一事实来源。
2. `DiagramLayout`：图形坐标、折线控制点、缩放和分组，只决定版面。
3. `CompiledModel`：基准值换算、端口排序、关联矩阵、局部元件矩阵、Kron 约简和状态索引。
4. `AnalysisResult`：绑定 `graphRevision`、`modelHash` 和求解器版本，只读显示，不回写输入。

应采用类型化端口：线路只能连接同电压等级母线端口；GFM、负荷和等值电源连接母线的注入端口；控制信号端口不得误接到电气端口。理想开关闭合可能引起节点收缩，不能一概用“大导纳”代替。

## 交互方案

- 左侧：元件库，首版包括母线、构网型变流器、等值电源、负荷、线路和开关。
- 中央：可缩放网络图，支持拖放、端口连线、断线、多选和自动布局。
- 右侧：所选元件的参数、单位、标幺基准、模型版本和数据来源。
- 下方：拓扑校核、网络约简和稳定性结果，可在网络图上叠加工作点、主导模态参与度与判据覆盖情况。

操作语义必须明确：

- 拖动元件：仅调整图形位置；
- 改接端口、开合开关：改变拓扑；
- 修改参数：改变边权或局部元件模型；
- 运行分析：冻结当前网络快照，先校核拓扑和工作点，再计算稳定性。

拓扑校核至少包括连通分量、孤岛参考源、悬空端口、非法自环、重复 ID、电压等级、平行支路、割边/割点和环路数。分析方法不支持的元件组合应显示“该模型尚未接入此分析方法”，不得给出伪结果。

## 可复用方案

- 画布直接采用 MIT 许可的 [React Flow](https://reactflow.dev/)；它已提供拖动、缩放、平移、多选、自定义端口和连接事件。领域模型仍由项目自行维护，不直接使用 React Flow 的 `nodes/edges` 作为计算输入。
- 自动布局可采用 [Eclipse ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html) 的正交布线思想；首版可先做简单分层布局，避免引入不必要依赖。
- [pandapower](https://pandapower.readthedocs.io/en/develop/elements.html) 用元件表描述母线、线路、变压器、开关等对象，并把网络转换为图执行拓扑搜索；借鉴其数据字段和校核项目，不引入其潮流内核作为当前 GFM 动态模型。
- [VeraGrid](https://github.com/SanPen/VeraGrid) 值得借鉴界面、领域对象、数值模型和结果分层；不复制其 Qt 界面代码。
- [PowerDynamics.jl](https://juliaenergy.github.io/PowerDynamics.jl/stable/ModelingConcepts/) 与 [NetworkDynamics.jl](https://juliadynamics.github.io/NetworkDynamics.jl/dev/mathematical_model/) 将节点和边分别建成局部输入—输出系统，再按图连接；项目借鉴其端口组合思想，不增加 Julia 运行依赖。
- [MATPOWER `makeYbus`](https://matpower.org/documentation/ref-manual/legacy/functions/makeYbus.html) 用首端、末端连接矩阵和支路端导纳组装节点导纳矩阵，可作为通用端口盖章的独立实现参照。

## 研究价值与实施次序

只做拖拽画布属于常规前端功能，创新性低。可辩护的技术增量应是：图形化网络经过类型检查后自动装配数学模型，并能够追溯某一支路或参数修改怎样改变约简网络导纳、闭环特征根和充分判据覆盖范围。

建议按以下次序实施：

1. 在不改变 `NetworkTopology/1.0` 计算契约的前提下，新增独立布局数据，接入 React Flow，完成母线、VSM、等值电源和线路的拖放与连线。
2. 增加命令式修改记录、撤销/重做、拓扑校核和“布局变化/拓扑变化/参数变化”差异摘要。
3. 将现有低频模型接入新画布，只开放其真实支持的参数；增加开关和 N−1 支路停运场景。
4. 扩展通用 dq 端口导纳装配、Kron 约简和论文判据接口，并对关联矩阵、端口方向、Kron 结果与作者代码建立反例门。
5. 研究局部增量灵敏度与拓扑消融；只有在预设实验中同时观察到判据覆盖改善且闭环参考一致，才讨论“拓扑信息降低保守性”。

## 风险边界

- 拓扑改变通常会改变潮流工作点；依赖工作点的变流器导纳必须重新线性化，不能沿用旧数据。
- 孤岛、无参考节点或病态内部子块会使 Kron 约简不可用，应报告“模型不可计算”或“数值待定”。
- 变压器、相移、π 型线路和受控元件不能都简化成标量拉普拉斯项；通用内核必须使用多端口局部矩阵。
- 图的代数连通度、割边和有效电阻可以解释网络结构，但不是论文稳定性充分判据。
- 使用全网模型给出元件灵敏度排序属于集中式辅助分析，不能仍称为完全分散式方法。

## 本轮停止条件

现有实现边界、可采用技术栈、数学装配形式和实施顺序均已获得源码或原始文档支持。继续检索同类编辑器不太可能改变“React Flow 交互层＋独立电气图模型＋端口装配＋Kron 约简”的决策，故在此停止扩展检索，进入设计冻结前的人工确认阶段。

## 2026-09-04 实施进展

- 上述第1、2项以及第3项的低频接入、线路投退和 N−1 单支路停运场景已经实现。`ACLine.in_service` 是向后兼容的运行状态字段；旧案例未提供该字段时按投运处理。
- 运行拓扑只计入投运线路。停运线路继续作为领域实体和图元保存，不进入连通性判定、同步刚度装配或 D–X 扫描目标。
- N−1 分析逐条移除当前投运线路。若参考母线无法到达全部母线，则将该工况标为形成孤岛而不作模态求解；若仍连通，则从该停运后拓扑重新建立完整低频状态矩阵，不沿用基准工况的极点。
- 当前输出只能回答“此降阶模型中，单条支路退出是否破坏连通性，以及连通工况的闭环主导模态如何变化”。它不替代交流潮流、线路热限、电压越限、短路故障或大扰动安全分析。
- 第4、5项仍属后续研究工作；在通用 `dq` 端口导纳、工作点重算和反例门完成前，不把本轮实现描述为论文充分判据的任意拓扑推广。
