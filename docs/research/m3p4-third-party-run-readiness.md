# M3.4 第三方运行确认的科学就绪性审计

## 1. 审计目的

M3.4 包含两个逻辑上不同的任务：其一是在隔离环境复跑 Sienna Test 08，确认上游固定基线；其二是把该19状态模型与团队16状态平均值 `dq` 模型作逐根特征值比较。前者只要求来源、版本、初值与运行环境可复现；后者还要求两个原始整机模型的方程、工作点、端口和状态空间具有明确对应关系。运行程序成功不等于跨模型验证成立。

为防止把“第三方代码可运行”越界写成“团队模型已获验证”，软件新增机器可读的 M3.4 进入门。该门只评价科学比较条件，不检测本机是否安装 Julia，也不运行 PSCAD。

## 2. 当前判定

上游固定 Test 08 的 Python 独立方程转写已经重现冻结初值与19个特征值，因此可以把 Julia 复跑作为来源基线确认。原始 Test 08 与团队整机模型仍不具备逐根特征值比较条件，当前五项未闭合门为：

1. 原始完整内环尚未同构；
2. 原始有功、无功功率测量端口不同；
3. 两个原始整机模型尚未在同一加载工作点完成平衡方程对齐；
4. Sienna 代数网络与团队动态外部 RL 线路尚未建立方程同构；
5. 原始整机状态维数仍为19与16，尚无覆盖全部状态的双射或经证明的约化关系。

共有六状态 LCL 方程门和双 PI 状态缩放门已经通过。静态网络中间层也已闭合：Test 08 的 `X=0.075 p.u.` 由100 MVA系统基值换算到2.75 MVA设备基值后为 `0.0020625 p.u.`；再将来源侧“变流器流向网络为正”的电流改写为团队侧“网络流向变流器为正”，三组独立电流探针的端电压差均为零。遗漏基值换算与遗漏电流方向反转的反例分别产生 `0.03262 p.u.` 和 `0.001845 p.u.` 的端电压差，均被门限拒绝。

上述静态网络等价仍只是零状态代数中间层。团队原始模型保留动态 RL 线路，故“原始外部网络方程同构”一项仍为未闭合；三个已通过的局部门也都不能代替整机门。

## 3. 决策规则

- 允许在隔离环境复跑固定 Julia 基线，并将结论限定为“确认上游 Test 08 在指定版本下可执行及其冻结结果可重现”。
- 在五项未闭合门全部通过前，不进行原始16状态与19状态模型的逐根特征值配对，不计算所谓“跨模型预测误差”。
- 若后续仅构造双方共有的同构化中间模型，必须继续使用“中间算例”名称，不得改称任一原始整机模型。
- PSCAD 固定轨迹仍属于上游证据；没有相应环境和实际运行记录时，不声称已经复跑。

可执行入口由 `backend/core/sienna_test08_run_readiness.py` 提供，并通过统一 Sienna 审计 API 返回。当前状态为 `not-ready`；它表示跨模型科学比较条件未齐备，不表示上游源码、团队软件或数值求解失败。
